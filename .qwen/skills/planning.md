# 📋 Planning Skill — Планирование задач

**Навык разбиения задач на подзадачи по 2-5 минут**

---

## 🎯 Назначение

Этот навык помогает разбивать большие задачи на маленькие, оцениваемые шаги (2-5 минут каждый), что делает разработку предсказуемой и снижает когнитивную нагрузку.

---

## 🚀 Использование

### Активация

```
/plan <описание задачи>

Примеры:
/plan Добавить виджет избранного
/plan Реализовать поиск по станциям
/plan Интегрировать новый API
```

---

## 📐 Принципы планирования

### Правило 2-5 минут

Каждая подзадача должна занимать **2-5 минут**:
- ✅ "Добавить переменную count" (2 мин)
- ✅ "Написать тест для count" (3 мин)
- ✅ "Реализовать инкремент" (4 мин)
- ❌ "Реализовать весь функционал" (30+ мин) — слишком большая!

### Структура задачи

```markdown
## Задача: <Название>

### Контекст
<Описание проблемы/возможности>

### Требования
- [ ] Требование 1
- [ ] Требование 2
- [ ] Требование 3

### План реализации
<Пошаговый план>

### Оценка времени
<Общее время>
```

---

## 🎯 Процесс планирования

### Шаг 1: Понять задачу

AI задаёт уточняющие вопросы:

```markdown
## Уточнение задачи

Прежде чем создать план, ответьте на вопросы:

1. **Какую проблему решаем?**
   - Что не работает сейчас?
   - Что должно работать после?

2. **Какие требования?**
   - Функциональные требования
   - Нефункциональные требования (производительность, etc.)

3. **Какие ограничения?**
   - Дедлайны
   - Технические ограничения
   - Зависимости от других задач

4. **Как будем тестировать?**
   - Критерии приёмки
   - Необходимые тесты
```

### Шаг 2: Создать план

```markdown
## План реализации

### Этап 1: Подготовка (5 мин)
- [ ] [2 мин] Изучить текущую структуру кода
- [ ] [3 мин] Создать файлы для нового компонента

### Этап 2: Реализация (20 мин)
- [ ] [3 мин] Написать unit тесты для логики
- [ ] [4 мин] Реализовать основную логику
- [ ] [3 мин] Написать widget тесты
- [ ] [5 мин] Реализовать UI компонент
- [ ] [5 мин] Интегрировать с существующим кодом

### Этап 3: Тестирование (10 мин)
- [ ] [5 мин] Запустить все тесты
- [ ] [3 мин] Исправить failing тесты
- [ ] [2 мин] Проверить вручную

### Этап 4: Документирование (5 мин)
- [ ] [3 мин] Добавить dartdoc комментарии
- [ ] [2 мин] Обновить README

**Итого: 40 минут**
```

### Шаг 3: Получить подтверждение

```markdown
## Подтверждение плана

План готов к реализации!

**Общее время:** 40 минут
**Количество шагов:** 12
**Сложность:** Средняя

Готовы начать? [yes/no]

Если yes, начну с первого шага.
Если no, укажите какие изменения внести.
```

## 🎯 Оценка сложности

### Уровни сложности

| Уровень | Время | Описание | Пример |
|---------|-------|----------|--------|
| **Trivial** | <10 мин | Простое изменение | Добавить константу |
| **Simple** | 10-30 мин | Одна функция/виджет | Добавить метод |
| **Medium** | 30-60 мин | Несколько файлов | Новый виджет с тестами |
| **Complex** | 1-3 часа | Новая фича | Интеграция API |
| **Large** | 3+ часа | Большая фича | Модуль с нуля |

### Формула оценки

```
Общее время = Σ(все подзадачи) + 20% буфер

Пример:
- Подзадачи: 40 минут
- Буфер (20%): 8 минут
- Итого: 48 минут
```

## 📊 Трекинг прогресса

### Шаблон трекинга

```markdown
## Прогресс задачи

**Задача:** <Название>
**Начало:** 14:00
**Плановое окончание:** 14:45

### Выполнено

- [x] [2 мин] Изучить структуру (2 мин ✅)
- [x] [3 мин] Создать файлы (4 мин ⚠️ +1)
- [ ] [5 мин] Написать тесты
- [ ] [5 мин] Реализовать логику

### Статус

**Прогресс:** 2/8 шагов (25%)
**Время затрачено:** 6 минут
**Время осталось:** 34 минуты
**Отклонение:** +1 минута
```

### Обновление статуса

```
/update-progress

Шаг 3 завершён за 6 минут (план: 5 мин)

Обновлённый прогресс:
- Выполнено: 3/8 шагов
- Время: 12 минут
- Отклонение: +2 минуты
```

## 🔧 Управление изменениями плана

### Когда обновлять план

```markdown
## Обновление плана

Обновите план если:

1. **Нашли непредвиденную сложность**
   - "Этот код сложнее чем думал"
   - "Нужно изучить дополнительную документацию"

2. **Изменились требования**
   - "Заказчик добавил новое требование"
   - "Нашли баг в смежном коде"

3. **Технические проблемы**
   - "Зависимость не работает"
   - "Нужно обновить Flutter"

4. **Переоценка времени**
   - "Шаг занял 10 мин вместо 3"
   - "Можно сделать быстрее другим способом"
```

### Формат обновления

```markdown
## Update Plan

**Причина:** Нашел дополнительную сложность

**Изменения:**
- Добавлен шаг 3a: Изучить документацию API (5 мин)
- Увеличен шаг 4: 5 мин → 8 мин

**Новое общее время:** 45 мин → 58 мин

**Утверждаете изменения?** [yes/no]
```

## 🎓 Best Practices

### ✅ DO

```markdown
// Разбивайте на атомарные шаги
- [x] [2 мин] Добавить переменную
- [x] [3 мин] Добавить тест
- [x] [4 мин] Реализовать метод

// Оценивайте реалистично
- [x] [5 мин] Написать тест (с запасом)

// Обновляйте прогресс
- [x] [5 мин] Шаг завершён за 6 мин
```

### ❌ DON'T

```markdown
// Не создавайте большие шаги
- [ ] [30 мин] Реализовать всё (слишком много!)

// Не оценивайте оптимистично
- [ ] [1 мин] Написать все тесты (нереально)

// Не забывайте обновлять
- [x] [5 мин] Шаг завершён (но не указано время)
```

## 📞 Интеграция с другими навыками

### Planning + TDD

```markdown
/plan Добавить поиск

План создан. Теперь запустите:
/tdd Реализовать поиск

TDD сессия будет следовать плану.
```

### Planning + Code Review

```markdown
/plan Добавить виджет

После реализации запустите:
/review

Code Review проверит качество.
```

### Planning + Debugging

```markdown
/plan Исправить баг

Если застрянете:
/debug <проблема>

Debugging поможет найти причину.
```
