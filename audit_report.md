
# Аудит ошибок и багов приложения SakhaLive

**Дата аудита:** 2026-03-09
**Версия приложения:** (не указана)
**Проверяемые аспекты:** Навигация, фоновые процессы, верстка, сетевые запросы, производительность, доступность.

## 1. Логика Navigation (IndexedStack / PageStorage)

### Текущая реализация
- Используется `PageView` с `KeepAliveWrapper` (кастомная обертка на `AutomaticKeepAliveClientMixin`).
- Для каждой вкладки задан `PageStorageKey` (radio, weather, horoscope, charts).
- Легкие вкладки (радио, погода) имеют `keepAlive: true`, тяжелые (гороскоп, чарты) – `keepAlive: false`.

### Потенциальные проблемы
1. **Отсутствие явного `PageStorage`** – ключи `PageStorageKey` могут не работать, если выше по дереву нет виджета `PageStorage`. В Flutter `PageStorage` обычно предоставляется `MaterialApp`, но гарантий нет.
2. **Потеря состояния тяжелых вкладок** – при `keepAlive: false` состояние (позиция прокрутки, введенные данные) сбрасывается при переключении. Это может ухудшить UX, если пользователь часто переключается между вкладками.
3. **Не используется `IndexedStack`** – альтернативный подход с сохранением состояния всех вкладок не реализован, что могло бы улучшить отзывчивость.

### Рекомендации
- Добавить `PageStorage` выше `PageView` для гарантированного сохранения состояния.
- Рассмотреть использование `IndexedStack` вместо `PageView` для мгновенного переключения без пересоздания.
- Для тяжелых вкладок оценить целесообразность `keepAlive: true` (если память позволяет).

## 2. Фоновые процессы (dispose VideoPlayerController и AudioPlayer)

### VideoPlayerController
- **Файл:** `lib/features/charts/presentation/widgets/video_ad_card.dart`
- **Найдено:** Контроллер создается в `_initVideoPlayer`, в `dispose()` вызывается `_controller?.dispose()`.
- **Флаг `_isDisposed`** предотвращает операции после уничтожения.
- **Вывод:** Утечки маловероятны, реализация корректна.

### AudioPlayer (just_audio)
- **Файл:** `lib/features/radio/data/radio_player.dart`
- **Найдено:** В методе `dispose()` для не‑Web платформ вызывается только `player!.stop()`, но не `player.dispose()`. Пояснение в коде: «Мы не диспозим player здесь, так как он общий для audioHandler».
- **Файл:** `lib/services/audio_handler.dart`
- **Найдено:** Класс `RadioAudioHandler` имеет метод `dispose()`, который вызывает `_player.dispose()`.
- **Проблема:** Неясно, вызывается ли `dispose()` у `RadioAudioHandler` при завершении работы приложения. `AudioService` может управлять жизненным циклом, но если приложение закрывается без остановки сервиса, возможна утечка.

### Рекомендации
- Убедиться, что `audioHandler.dispose()` вызывается при выходе из приложения (например, в `main` перед завершением).
- В `RadioPlayer.dispose()` для не‑Web всё же вызывать `player.dispose()`, если audioHandler больше не нужен (или гарантировать, что audioHandler переживает RadioPlayer).

## 3. Верстка экрана Гороскопа (RenderFlex overflow)

### Текущая реализация
- **Файл:** `lib/features/horoscope/presentation/widgets/horoscope_view.dart`
- Текст предсказания отображается в `Text` без `maxLines` и `overflow` (строки 292‑302).
- Размер шрифта фиксирован (`fontSize: 16`), не адаптируется к системным настройкам доступности.

### Потенциальные проблемы
1. **Очень длинный текст** может выйти за границы карточки, вызвав `RenderFlex overflowed by ... pixels`.
2. **Увеличенный системный шрифт** может привести к тому же эффекту.
3. Отсутствие прокрутки внутри карточки (хотя весь экран прокручивается) – текст может «растянуть» карточку, но это допустимо в `SingleChildScrollView`.

### Рекомендации
- Добавить `maxLines: 10` (или другое разумное ограничение) и `overflow: TextOverflow.ellipsis`.
- Либо использовать `Expanded` и `SingleChildScrollView` внутри карточки для прокрутки длинного текста.
- Применить `MediaQuery.textScaleFactor` для адаптации размера шрифта.

## 4. Сетевые запросы (офлайн режим)

### Гороскоп
- **Файл:** `lib/features/horoscope/data/services/horoscope_service.dart`
- **Стратегия:** Кэш → APIVerve → API Ninjas → запасные тексты.
- **Плюсы:** При отсутствии интернета пользователь увидит запасной прогноз (не будет бесконечной загрузки).
- **Минусы:** Нет явного сообщения «нет соединения», данные могут быть устаревшими.

### Погода
- **Файл:** `lib/features/weather/presentation/weather_screen.dart`
- **Обработка ошибок:** Используется `AsyncValue.when` с отдельным виджетом `_buildErrorView`.
- **Отображение:** Показывается иконка `wifi_off_outlined`, текст «Ошибка сети», кнопка «Повторить». Дополнительно выводится snackbar.
- **Вывод:** UX продуман, но snackbar может дублировать сообщение.

### Радио и чарты
- Не проверялись детально, но вероятно имеют базовую обработку сетевых ошибок (например, через `try-catch` в провайдерах).

### Общая рекомендация
- Ввести единый компонент «Нет подключения к интернету» для всех экранов, зависящих от сети.
- Убедиться, что при потере соединения не происходит бесконечной индикации загрузки.

## 5. Производительность (рендеринг, анимации)

### Находки
1. **Использование RepaintBoundary** – в `home_screen.dart` `PageView` обернут в `RepaintBoundary`, что изолирует перерисовку и улучшает производительность.
2. **Селективные подписки** – во многих местах используется `ref.watch` с `select`, что уменьшает количество перестроений.
3. **Анимации** – в `horoscope_view.dart` анимация появления карточек использует `AnimationController`. Анимация перезапускается при каждом изменении текста гороскопа, что может приводить к лишним вычислениям.
4. **Отсутствие const виджетов** – многие виджеты (например, `SizedBox`) не помечены как `const`, что создает лишние объекты при перестроении.
5. **Blur эффекты** – `BackdropFilter` с размытием в нижней панели навигации может быть дорогим на старых устройствах, но используется локально.

### Рекомендации
- Добавить `const` где возможно (например, `const SizedBox(...)`).
- Рассмотреть возможность отключения анимаций на слабых устройствах (через `MediaQuery.disableAnimations`).
- Проверить, не вызывает ли `SakhaFuturism.ambientBackground` тяжелых вычислений. Если да – добавить кэширование.

## 6. Доступность (семантические теги, контрастность, размеры тапов)

### Находки
1. **Семантические теги** – в коде отсутствуют явные `Semantics` виджеты. Flutter предоставляет базовую семантику автоматически, но для кастомных интерактивных элементов это может быть недостаточно.
